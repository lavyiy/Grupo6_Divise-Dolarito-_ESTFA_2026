19. Consultas (Querys): ABM de Usuarios

Las consultas que se detallan a continuación corresponden a la base de datos PostgreSQL que sustenta el backend de la plataforma Divise. En todas ellas los valores dinámicos se transmiten como parámetros ($1, $2, ...), lo que previene ataques de inyección SQL. Las consultas escritas con el cliente pg utilizan esa sintaxis de parámetros; las que se ejecutan mediante el cliente de Supabase aplican filtros tipados (.eq, .ilike), que el cliente escapa de forma automática.

19.1 ABM de Usuarios

Rol y descripción
- Usuario Visitante: accede a cotizaciones, calculadora y gráficos sin registrarse.
- Usuario Registrado: guarda favoritos, configura alertas y consulta su historial.
- Administrador: gestiona usuarios, parámetros fiscales y monitorea el estado de las APIs.

Alta: validación de email único, hashing de contraseña con Bcrypt y cuenta creada con estado activo en TRUE.
Modificación: el usuario actualiza nombre, email y divisa base; el cambio de contraseña exige la clave vigente como confirmación de identidad.
Baja: baja lógica (los campos activo y deleted_at se actualizan), preservando los registros históricos; las alertas y los favoritos asociados permanecen en la base.

1. Alta (Create / Insert):
INSERT INTO usuarios (nombre, email, password_hash, divisa_base_id)
VALUES ($1, $2, $3, $4)
RETURNING id_usuario, nombre, email, divisa_base_id, created_at;

2. Lectura (Read / Seleccionar un usuario):
SELECT u.id_usuario, u.nombre, u.email, u.divisa_base_id, d.codigo AS divisa_base_codigo, u.email_verificado, u.two_factor_enabled, u.whatsapp_phone, u.created_at
FROM usuarios u
LEFT JOIN divisas d ON u.divisa_base_id = d.id_divisa
WHERE u.id_usuario = $1 AND u.activo = TRUE AND u.deleted_at IS NULL;

3. Listado de usuarios registrados:
SELECT u.id_usuario, u.nombre, u.email, u.divisa_base_id, d.codigo AS divisa_base_codigo, u.created_at
FROM usuarios u
LEFT JOIN divisas d ON u.divisa_base_id = d.id_divisa
WHERE u.activo = TRUE AND u.deleted_at IS NULL
ORDER BY u.id_usuario ASC;

4. Modificación (Update / Actualizar perfil):
UPDATE usuarios
SET nombre = $1, email = $2, divisa_base_id = $3, updated_at = CURRENT_TIMESTAMP
WHERE id_usuario = $4 AND activo = TRUE AND deleted_at IS NULL;

5. Baja (Delete / Baja lógica):
UPDATE usuarios
SET activo = FALSE, deleted_at = CURRENT_TIMESTAMP, updated_at = CURRENT_TIMESTAMP
WHERE id_usuario = $1;

6. Inicio de sesión (búsqueda por email; el hash se compara con Bcrypt en el backend):
SELECT id_usuario, nombre, email, password_hash, divisa_base_id, email_verificado, two_factor_enabled, activo
FROM usuarios
WHERE lower(email) = lower($1)
LIMIT 1;

7. Cambio de contraseña (previa validación de la contraseña actual):
UPDATE usuarios
SET password_hash = $1, reset_token = NULL, reset_token_expires = NULL, updated_at = CURRENT_TIMESTAMP
WHERE id_usuario = $2;

8. Recuperación de contraseña (alta del token y de su vencimiento):
UPDATE usuarios
SET reset_token = $1, reset_token_expires = $2
WHERE lower(email) = lower($3);

9. Validación del token de recuperación (solo si no expiró):
SELECT id_usuario, email
FROM usuarios
WHERE reset_token = $1 AND reset_token_expires > $2
LIMIT 1;

10. Verificación de email por código de 6 dígitos:
SELECT id_usuario, email
FROM usuarios
WHERE lower(email) = lower($1) AND verif_codigo = $2 AND verif_expira > $3
LIMIT 1;

11. Confirmación del email verificado:
UPDATE usuarios
SET email_verificado = TRUE, verif_codigo = NULL, verif_expira = NULL, verif_token = NULL
WHERE id_usuario = $1;

12. Activar o desactivar la autenticación en dos pasos (2FA):
UPDATE usuarios
SET two_factor_enabled = $1
WHERE id_usuario = $2;

13. Guardar la configuración de notificaciones por WhatsApp:
UPDATE usuarios
SET whatsapp_phone = COALESCE($1, whatsapp_phone), whatsapp_api_key = COALESCE($2, whatsapp_api_key)
WHERE id_usuario = $3;

19.2 Cotizaciones en Tiempo Real

Unión (JOIN) entre las tablas tipos_de_cambio y divisas que retorna la última cotización de cada activo por mercado, ordenada por fecha de actualización para quedarse con el registro más reciente de cada uno.

SELECT DISTINCT ON (d.id_divisa, tc.tipo_mercado) d.id_divisa, d.codigo, d.nombre, CASE WHEN lower(d.tipo) IN ('cripto', 'crypto') THEN 'crypto' ELSE d.tipo END AS tipo, d.coingecko_id, tc.precio_compra, tc.precio_venta, tc.tipo_mercado, tc.fecha_actualizacion
FROM tipos_de_cambio tc
JOIN divisas d ON tc.id_divisa = d.id_divisa
ORDER BY d.id_divisa, tc.tipo_mercado, tc.fecha_actualizacion DESC, tc.id_tipo_cambio DESC;

19.3 Historial por Activo

Búsqueda ordenada cronológicamente de las cotizaciones registradas de un activo conforme a su id_divisa, su mercado y un rango temporal determinado (por ejemplo, para los gráficos de 24h, 7d, 30d y 1a).

SELECT tc.fecha_actualizacion, tc.precio_compra, tc.precio_venta, tc.tipo_mercado
FROM tipos_de_cambio tc
JOIN divisas d ON tc.id_divisa = d.id_divisa
WHERE tc.id_divisa = $1 AND tc.tipo_mercado = $2 AND tc.fecha_actualizacion BETWEEN $3 AND $4
ORDER BY tc.fecha_actualizacion ASC;

Historial de consultas del usuario (registro de cada conversión realizada):

SELECT id_historial, par_consultado, valor_momento, fecha
FROM historial_de_consultas
WHERE id_usuario = $1 AND fecha BETWEEN $2 AND $3
ORDER BY fecha DESC;

19.4 Alertas Pendientes

Filtrado de la tabla alertas según el booleano notificada en FALSE, destinado a la evaluación de umbrales y al envío de notificaciones (correo o WhatsApp).

SELECT a.id_alerta, u.email, u.whatsapp_phone, a.codigo_divisa, a.condicion, a.valor_limite
FROM alertas a
JOIN usuarios u ON a.id_usuario = u.id_usuario
WHERE a.notificada = FALSE AND u.activo = TRUE
ORDER BY a.id_alerta;

Marcado de la alerta como notificada una vez disparada:

UPDATE alertas
SET notificada = TRUE
WHERE id_alerta = $1;

19.5 Favoritos

Consulta filtrada por el id_usuario de la sesión activa, que retorna las divisas marcadas como favoritas para su presentación en el panel personalizado.

SELECT f.id_favorito, d.codigo, d.nombre, f.notificacion_activa, f.created_at
FROM favoritos f
JOIN divisas d ON f.id_divisa = d.id_divisa
WHERE f.id_usuario = $1
ORDER BY f.created_at ASC;

Agregar un favorito (la restricción UNIQUE(id_usuario, id_divisa) evita duplicados):

INSERT INTO favoritos (id_usuario, id_divisa)
VALUES ($1, $2)
ON CONFLICT (id_usuario, id_divisa) DO NOTHING;

Quitar un favorito:

DELETE FROM favoritos
WHERE id_usuario = $1 AND id_divisa = $2;
