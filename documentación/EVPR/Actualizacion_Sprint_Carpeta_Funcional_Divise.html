1. Resumen Ejecutivo de la Actualización

El presente documento formaliza la incorporación de mejoras operativas, corrección de inconsistencias en la entrada de datos numéricos regionales, habilitación del rol administrativo con auditoría de mensajería Gmail y resolución de problemas de maquetación en ventanas modales.

1. Calculadora con Formato Argentino

Soporte para múltiples puntos en millones (ej. 15.000.000), punto en miles (15.000), coma decimal (15.000,50) y prevención de errores NaN.

2. Rol Administrador y Auditoría Gmail

Módulo protegido /dashboard/admin con visor histórico de todos los correos enviados, códigos de verificación de 6 dígitos y gestión de roles.

3. Modal de Contacto Directo

Acceso directo al correo institucional deviseproyect@gmail.com (con copiado en un clic), WhatsApp y formulario integrado.

4. Aislamiento CSS de Ventanas Modales

Resolución de colisiones CSS de selectores globales para evitar desacomodamientos al abrir la configuración de alertas o de perfil.

5. Selector y Carga de Foto de Perfil

Subida de imágenes locales comprimidas en cliente a Base64 más una galería de 8 avatares vectoriales prediseñados.

6. Validación de Correo en Autenticación

Mensaje unificado: "El correo electrónico no es válido o no está registrado en la base de datos." en Login y Recuperación.

2. Historias de Usuario Agregadas y Actualizadas

HU #51 – Soporte de Formato Numérico Argentino y Grandes Cifras
Como usuario de la plataforma Divise, quiero ingresar montos utilizando la convención argentina con puntos para separar miles y comas para decimales, para convertir divisas y configurar alertas sin que el sistema rechace montos grandes o genere cálculos erróneos.
Criterios de Aceptación:
  • 15.000 es interpretado exactamente como 15 mil unidades monetarias.
  • 15.000.000 es interpretado como 15 millones sin errores de NaN ni truncamiento.
  • 15.000.000,50 respeta los decimales tras la coma.
  • Muestra mensaje de error en vivo ante caracteres no válidos.
HU #52 – Canal Directo de Contacto y Asistencia con Administradores
Como usuario o visitante, quiero acceder de forma rápida a un canal de contacto directo con el equipo administrador, para solicitar asistencia, reportar incidencias técnicas o consultar sobre el servicio.
Criterios de Aceptación:
  • Botón visible de "Contacto" en barra de navegación, menú lateral y pantalla de perfil.
  • Muestra el correo deviseproyect@gmail.com con botón de copiado inmediato.
  • Enlace directo a WhatsApp oficial con mensaje preconfigurado.
  • Formulario de contacto para enviar mensaje directo al servidor.
HU #53 – Panel de Control del Administrador y Registro de Gmails Enviados
Como administrador del sistema, quiero contar con una interfaz dedicada para auditar los correos enviados y gestionar usuarios, para asegurar la correcta entrega de códigos de seguridad y controlar privilegios.
Criterios de Aceptación:
  • Ruta protegida /dashboard/admin accesible únicamente para roles autorizados.
  • Tabla con historial de correos enviados: destinatario, asunto, código de 6 dígitos, estado y fecha/hora.
  • Filtro en tiempo real por correo electrónico o código.
  • Listado de usuarios con capacidad de ascender o remover el rol administrador.
HU #54 – Personalización y Foto de Perfil de Usuario
Como usuario con sesión iniciada, quiero cargar una fotografía propia o seleccionar un avatar temático, para identificar mi cuenta dentro del sistema.
Criterios de Aceptación:
  • Carga de imágenes JPG, PNG o WEBP locales desde el dispositivo del usuario.
  • Compresión automática a 256x256 px en formato DataURL Base64 para minimizar consumo de ancho de banda.
  • Galería con 8 avatares vectoriales integrados.
  • Persistencia en base de datos y refresco instantáneo en Navbar y Perfil.

3.1. Esquema de Base de Datos (Migración SQL 011_admin_and_email_logs.sql)

-- Ampliación de la tabla de usuarios
ALTER TABLE usuarios 
  ADD COLUMN IF NOT EXISTS rol VARCHAR(30) DEFAULT 'usuario',
  ADD COLUMN IF NOT EXISTS es_admin BOOLEAN DEFAULT false,
  ADD COLUMN IF NOT EXISTS foto_perfil TEXT;

-- Tabla de auditoría de correos enviados (Gmail / SMTP / Mock)
CREATE TABLE IF NOT EXISTS emails_enviados (
  id_log SERIAL PRIMARY KEY,
  destinatario VARCHAR(255) NOT NULL,
  asunto VARCHAR(255) NOT NULL,
  tipo VARCHAR(50) NOT NULL,
  codigo VARCHAR(20),
  estado VARCHAR(20) DEFAULT 'enviado',
  error_detalle TEXT,
  metadata JSONB,
  creado_en TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_emails_enviados_dest ON emails_enviados(destinatario);
CREATE INDEX idx_emails_enviados_fecha ON emails_enviados(creado_en DESC);

3.2. Normalización de Cifras Regionales (src/utils.js)

El motor matemático implementa la función parseArgentineNumber(raw). El algoritmo evalúa la posición de puntos y comas: si un punto precede exactamente a 3 dígitos en un número sin comas o con coma posterior, lo interpreta como separador de miles. Asimismo, números con múltiples puntos (ej. 15.000.000) son normalizados eliminando los puntos antes de la conversión a punto flotante IEEE 754, erradicando por completo los errores de tipo NaN.
